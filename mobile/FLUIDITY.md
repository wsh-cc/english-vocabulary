# Android 0.1.6 交互与缓存优化

范围：`mobile/`；保留现有配色、布局与学习/保存/同步规则。

| 问题 | 改动 |
| --- | --- |
| Tab 硬切，回到词库丢失搜索和位置 | 缓存五个 Tab，恢复搜索、筛选、阅读篇目与各页滚动位置 |
| 点击反馈与页面渲染抢占时间 | 按下即反馈，底栏先更新选中态，内容以较低优先级渲染 |
| 页面频繁重建、重复计算 | `memo`、稳定回调、摘要缓存；隐藏页使用 React Activity 暂停监听和计时器 |
| 页面滑动偏快、进出节奏不同 | 页面轻移 24 px，进出均为 320 ms；弹层仍为进入 240 ms、退出 180 ms；统一 `cubic-bezier(.22,.61,.36,1)` |
| 快速反向操作跳回动画起点 | 从正在显示的位置接续；过期动画取消，最终只保留最新页面 |
| 从练习返回今日途中闪回词库 | 退出练习与目的页更新合并为一次切换 |
| 减少动态效果 | 关闭位移和过渡；设置在动画中变化时立即结束动画 |
| 高刷新率 | 使用浏览器合成动画，无固定 60 Hz 计时循环；Android 15+ 前台 WebView 请求系统 HIGH 帧率类别 |

## 0.1.6 旧页闪回修复

`node scripts/verify-fluidity.mjs --flash` 在 0.1.5 上复现：普通的一次「今日 → 阅读」切换即可触发，旧页透明度在动画清理时从 0 回到 1，逐帧采样记录到旧页再次显示。此前的检查只确认最终页面、动画时长和残留对象，遗漏了结束瞬间的可见性。

原因：WAAPI 的填充效果被取消时恢复底层样式，而 React 稍后才把旧页隐藏。现在非当前页面的底层透明度为 0，正在关闭的弹层也保持透明；动画从已记录的位置继续，清理前后没有透明度反弹。页面进出使用相同的 320 ms，避免一页先退完、另一页仍在进入。

新增 5 项检查：普通/滚动切换逐帧不反弹、反向切换保持两页的位置和透明度、4 倍 CPU 降速下连续切换 60 次不露出无关缓存页、最终停在最后一次选择、页面及弹层清理动画后仍保持透明。验证结果见 `output/playwright/fluidity-flash.json`。

`src/Motion.tsx` 管理页面/弹层生命周期；`src/Motion.css` 集中动效参数。只动画化透明度与位移，不逐帧修改尺寸或位置。动画结束后释放动画对象，不常驻 `will-change` 图层。

生产 CSS 可能将 `240ms` 压缩为 `.24s`，读取时统一换算成毫秒；回归检查直接验证生产包动画时长。弹层退出期间保留滚动锁、焦点管理与嵌套返回处理。

依据：[React Activity](https://react.dev/reference/react/Activity)、[Android 自适应刷新率](https://developer.android.com/develop/ui/views/animations/adaptive-refresh-rate)。刷新率仍由设备、系统节电和温控策略决定。

## 有上限的空间换时间

`src/study-cache.ts` 为账号界面提供共享缓存；`src/StudyCache.tsx` 管理作用域和空闲预加载。

| 缓存 | 容量与刷新规则 |
| --- | --- |
| 词库索引 | 一份当前词库，复用 ID、义项、级别及小写搜索文本；导入/恢复后重建 |
| 搜索结果 | LRU 最多 24 项、12,000 个词条引用；不复制词条，超过 128 字符的查询不缓存；熟悉程度变化时失效 |
| 阅读解析 | LRU 最多 12 篇、64,000 字符；按完整原文区分内容版本 |
| 统计、覆盖率、复习日程 | 每个 CET 级别至多一份；按事件、阅读、进度和词库快照刷新；到期时间二分定位，北京日期变化重算七日安排 |
| 主页面 | 固定五个 Tab；保持搜索、阅读篇目和滚动位置，隐藏时暂停副作用 |
| 临时页面 | 练习与弹层只保留到退场结束；立即释放动画对象和相关监听 |

登录后的空闲时间分批准备词库索引和前两篇阅读，阅读时预解析后两篇。每个空闲回调最多一项任务，页面隐藏、卸载或材料变化时取消待办；没有空闲回调支持时使用可取消的低频定时器。内容已在 APK 本地，不额外发网络请求。账号切换或登录界面出现时销毁缓存作用域。

词库列表使用独立的 `memo` 组件；搜索输入先响应，结果延后更新，相同结果不重绘列表。页面时钟在后台停用，回到前台重新校准，避免过期复习计数。

## 验证

使用独立浏览器的本机预览账号，不使用真实账号或学习记录。先启动开发服务（5188），打开 `mobile-fluidity` Playwright 会话并点击「查看本机界面预览」；构建后在 5189 启动生产预览。

```powershell
npm.cmd run dev
# 另一个终端
npx.cmd --yes --package @playwright/cli playwright-cli -s=mobile-fluidity open http://127.0.0.1:5188 --browser chrome
# 点击「查看本机界面预览」后
npm.cmd run build
node node_modules/vite/bin/vite.js preview --host 127.0.0.1 --port 5189 --strictPort
# 再另一个终端；measure 会验证预览账号身份，并切换到生产预览
node scripts/verify-fluidity.mjs --measure
node scripts/verify-fluidity.mjs
node scripts/verify-fluidity.mjs --extended
node scripts/verify-fluidity.mjs --flash
node scripts/verify-fluidity.mjs --lifetime
node scripts/verify-fluidity.mjs --cache
```

结果保存在 `output/playwright/fluidity-*.json`：9 项基本检查、14 项扩展检查、10 项生命周期检查、5 项闪回检查，以及正常/4 倍 CPU 降速下各 30 次切换。覆盖状态与滚动恢复、实际动画时长、快速连点、嵌套返回、输入草稿、焦点/滚动锁恢复、练习进入退出、浅深色与 320 px 窄屏。

47 项手机端回归覆盖学习逻辑、缓存淘汰、数据变化、导入恢复、精确到期、时钟回退、北京时间跨日和预加载取消。原生构建同时执行 10 项单元测试、release lint 和设备测试 APK 编译；设备测试未连接真机执行。

2026-10-18 的 0.1.6 生命周期检查：结束练习后只保留五个主 Tab。200 次快速切换后节点数 1714 → 1714、监听数 437 → 437，回收后堆增长约 0.23 MiB；另做 12 轮弹层/练习开关，节点和监听数不增长，堆增长约 0.24 MiB。此有限压力测试未发现持续累积，不等同于长期真机无泄漏证明。

0.1.5 缓存测量参考：使用 10,000 条合成记录、10 个重复查询，五批各 300 次取中位数，搜索计算约 0.755 ms → 0.001 ms，统计约 0.748 ms → 低于计时分辨率。两种实现结果一致；这是热缓存计算耗时，不代表整页响应提升同等倍数。缓存命中后保留 10 项查询、5,313 个词条引用。0.1.6 未改动缓存实现。

0.1.6 最终构建：2026-10-18 桌面 Chromium、393 × 852 测量（单轮样本，受调度波动影响）：

| 条件 | 30 次切换页面就绪 P95 | 超过 50 ms 的主线程任务 |
